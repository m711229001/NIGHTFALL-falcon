## 🔍 الثغرات

### 1. [MEDIUM] Open Redirect in 'url'

**التصنيف:** OpenRedirect

**🎯 CVSS:** 6.1
  
**Vector:** `CVSS:3.1/AV:N/AC:L/PR:N/UI:R/S:C/C:L/I:L/A:N`
  
**⚠️ الأولوية:** 3

**🔗 رابط PoC (انسخه في المتصفح):**

```
https://httpbin.org/redirect-to?url=https%3A%2F%2Fevil.example.com%2F
```

**الرابط الأصلي:** `https://httpbin.org/redirect-to?url=test`

**📌 الباراميتر:** `url`

**💉 الحمولة:** `https://evil.example.com/`

**📝 الشرح:**

الثغرة هي Open Redirect (إعادة توجيه مفتوحة) في خدمة httpbin.org عبر المسار /redirect-to. التطبيق يأخذ قيمة البارامتر 'url' ويعيد توجيه المستخدم إليها دون أي تحقق من النطاق أو القائمة البيضاء. هذا يسمح للمهاجم بإنشاء روابط تبدو شرعية (تنتمي إلى httpbin.org) لكنها تنقل الضحية إلى موقع خبيث. الخطورة تكمن في استخدامها في حملات التصيّد، سرقة OAuth tokens، وتجاوز فلاتر الروابط في التطبيقات والبريد الإلكتروني.

**🎬 خطوات الاستغلال:**

1. يقوم المهاجم ببناء رابط يستخدم نطاقاً موثوقاً (httpbin.org) مع بارامتر url يحتوي على الموقع الخبيث.
2. يتم ترميز الرابط الخبيث (URL encoding) لتجاوز بعض الفلاتر البسيطة.
3. يرسل المهاجم الرابط للضحية عبر البريد أو وسائل التواصل.
4. الضحية يرى النطاق الموثوق httpbin.org ويضغط على الرابط.
5. الخادم يستجيب بـ HTTP 302 Location: https://evil.example.com/.
6. المتصفح يتبع التوجيه تلقائياً إلى الموقع الخبيث.
7. الموقع الخبيث يمكن أن يحاكي صفحة تسجيل دخول لسرقة بيانات الاعتماد.
8. يمكن استخدام الثغرة أيضاً في تدفق OAuth لسرقة authorization codes عبر redirect_uri غير مُقيّد.
9. المهاجم يجمع البيانات المسروقة أو يثبّت برمجيات خبيثة.

**💻 كود PoC (جاهز للتنفيذ):**

```python
import requests

# رابط PoC الكامل الذي يحتوي على البارامتر والحمولة الخبيثة
POC_URL = "https://httpbin.org/redirect-to?url=https%3A%2F%2Fevil.example.com%2F"

def main():
    # تعطيل التحقق من الشهادة لتجنب مشاكل SSL في بعض البيئات
    # allow_redirects=False لنرى استجابة التوجيه نفسها (302) بدلاً من اتباعها
    try:
        response = requests.get(POC_URL, allow_redirects=False, timeout=10, verify=False)
    except requests.exceptions.RequestException as e:
        print(f"[!] فشل الاتصال: {e}")
        return

    # طباعة كود الحالة (يجب أن يكون 302 Found)
    print(f"[+] Status Code: {response.status_code}")

    # طباعة ترويسة Location التي تحتوي على الموقع الخبيث
    location = response.headers.get("Location", "")
    print(f"[+] Location Header: {location}")

    # التحقق من نجاح إعادة التوجيه إلى النطاق الخبيث
    if "evil.example.com" in location:
        print("[✓] الثغرة مؤكدة: إعادة توجيه مفتوحة إلى نطاق خارجي خبيث!")
    else:
        print("[-] لم يتم اكتشاف إعادة توجيه خبيثة.")

    # طباعة أول 500 حرف من جسم الاستجابة للتوثيق
    print("\n[+] Response Body (first 500 chars):")
    print(response.text[:500])

if __name__ == "__main__":
    main()
```

**🛠️ الإصلاح:**

لمنع ثغرات Open Redirect يجب: (1) تجنب استخدام مدخلات المستخدم مباشرة في ترويسة Location. (2) استخدام قائمة بيضاء (allowlist) للنطاقات المسموح بها. (3) إذا كان لا بد من التوجيه الديناميكي، استخدم معرّفات داخلية (مثل mapping ID -> URL) بدلاً من تمرير URL كامل. (4) التحقق من أن الرابط يبدأ بـ '/' (مسار نسبي) ورفض أي رابط يحتوي على '://' أو '//'. (5) إضافة صفحة تحذير وسيطة عند التوجيه لنطاق خارجي. (6) استخدام Content-Security-Policy وX-Frame-Options كطبقات دفاع إضافية.

**🛠️ كود الإصلاح:**

```python
from urllib.parse import urlparse
from flask import Flask, request, redirect, abort

app = Flask(__name__)

# قائمة بيضاء بالنطاقات المسموح بها
ALLOWED_HOSTS = {"example.com", "www.example.com", "trusted-partner.com"}

@app.route("/redirect-to")
def safe_redirect():
    target = request.args.get("url", "")

    # رفض الروابط الفارغة
    if not target:
        abort(400, "Missing url parameter")

    # السماح فقط بالمسارات النسبية التي تبدأ بـ / وليس //
    if target.startswith("/") and not target.startswith("//"):
        return redirect(target, code=302)

    # تحليل الرابط المطلق والتحقق من النطاق
    parsed = urlparse(target)

    # رفض أي مخطط غير http/https
    if parsed.scheme not in ("http", "https"):
        abort(400, "Invalid scheme")

    # التحقق من النطاق مقابل القائمة البيضاء
    if parsed.hostname not in ALLOWED_HOSTS:
        abort(400, "Redirect target not allowed")

    return redirect(target, code=302)

if __name__ == "__main__":
    app.run(debug=False)
```
