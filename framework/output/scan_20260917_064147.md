## 🔍 الثغرات

### 1. [MEDIUM] Open Redirect in 'url'

**التصنيف:** OpenRedirect

**🎯 CVSS:** 6.1
  
**Vector:** `CVSS:3.1/AV:N/AC:L/PR:N/UI:R/S:C/C:L/I:L/A:N`
  
**⚠️ الأولوية:** 3

**🔗 رابط PoC (انسخه في المتصفح):**

```
https://httpbin.org/redirect-to?url=https%3A%2F%2Fevil.example.com%2F
```

**الرابط الأصلي:** `https://httpbin.org/redirect-to?url=test`

**📌 الباراميتر:** `url`

**💉 الحمولة:** `https://evil.example.com/`

**📝 الشرح:**

الثغرة هي Open Redirect (إعادة توجيه مفتوحة) في نقطة النهاية /redirect-to في httpbin.org. التطبيق يأخذ قيمة الباراميتر url ويعيد توجيه المستخدم إليها دون أي تحقق من النطاق أو القائمة البيضاء. هذا يسمح للمهاجم بإنشاء روابط تبدو موثوقة (تنتمي إلى httpbin.org) لكنها تنقل الضحية إلى موقع خبيث. خطورتها تكمن في استخدامها في حملات التصيّد، سرقة بيانات الاعتماد، وتجاوز فلاتر الأمان التي تعتمد على النطاق.

**🎬 خطوات الاستغلال:**

1. يقوم المهاجم بإنشاء رابط يحمل النطاق الموثوق httpbin.org مع باراميتر url يشير إلى موقعه الخبيث.
2. يرسل الرابط إلى الضحية عبر البريد الإلكتروني أو وسائل التواصل.
3. يرى الضحية النطاق httpbin.org ويثق به ويضغط على الرابط.
4. يستجيب الخادم برمز HTTP 302 مع ترويسة Location تشير إلى https://evil.example.com/.
5. يقوم المتصفح تلقائياً بإعادة توجيه الضحية إلى الموقع الخبيث.
6. يستغل المهاجم ذلك لسرقة بيانات الاعتماد أو تنزيل برمجيات خبيثة.
7. يمكن استخدام نفس الأسلوب لتجاوز فلاتر OAuth أو SSRF عبر إعادة التوجيه.

**💻 كود PoC (جاهز للتنفيذ):**

```python
import requests

# رابط PoC الكامل الذي يحتوي على الباراميتر والحمولة
POC_URL = "https://httpbin.org/redirect-to?url=https%3A%2F%2Fevil.example.com%2F"

# تعطيل التحقق من الشهادات لتجنب مشاكل SSL أثناء الاختبار
response = requests.get(POC_URL, allow_redirects=False, verify=False)

# طباعة رمز الحالة المتوقع 302
print("Status Code:", response.status_code)

# طباعة ترويسة Location التي تحتوي على الوجهة الخبيثة
print("Location Header:", response.headers.get("Location"))

# التحقق من نجاح إعادة التوجيه
if response.status_code in (301, 302, 303, 307, 308):
    print("[+] Open Redirect confirmed! Redirecting to:", response.headers.get("Location"))
else:
    print("[-] No redirect detected.")
```

**🛠️ الإصلاح:**

يجب التحقق من صحة عنوان URL المستهدف قبل إعادة التوجيه. أفضل الممارسات:
1. استخدام قائمة بيضاء (allowlist) للنطاقات المسموح بها.
2. رفض العناوين التي تحتوي على مخططات غير آمنة مثل javascript: أو data:.
3. استخدام مسارات نسبية بدلاً من عناوين URL مطلقة.
4. إضافة تحقق من النطاق باستخدام urllib.parse.
5. تسجيل محاولات إعادة التوجيه المشبوهة ومراقبتها.

**🛠️ كود الإصلاح:**

```python
from urllib.parse import urlparse
from flask import Flask, request, redirect, abort

app = Flask(__name__)

# قائمة بيضاء للنطاقات المسموح بها
ALLOWED_HOSTS = {"httpbin.org", "www.httpbin.org"}

@app.route("/redirect-to")
def safe_redirect():
    target = request.args.get("url", "")
    parsed = urlparse(target)

    # رفض المخططات غير الآمنة
    if parsed.scheme not in ("http", "https"):
        abort(400, "Invalid scheme")

    # التحقق من النطاق ضمن القائمة البيضاء
    if parsed.hostname not in ALLOWED_HOSTS:
        abort(400, "Host not allowed")

    return redirect(target, code=302)

if __name__ == "__main__":
    app.run()
```
