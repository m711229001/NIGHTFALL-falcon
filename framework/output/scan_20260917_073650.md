### 2. [HIGH] CORS Misconfiguration

**التصنيف:** CORS

**🎯 CVSS:** 8.1
  
**Vector:** `CVSS:3.1/AV:N/AC:L/PR:N/UI:R/S:U/C:H/I:H/A:N`
  
**⚠️ الأولوية:** 1

**🔗 رابط PoC (انسخه في المتصفح):**

```
https://httpbin.org?Origin=https://evil.httpbin.org
```

**الرابط الأصلي:** `https://httpbin.org`

**📌 الباراميتر:** `Origin`

**💉 الحمولة:** `https://evil.example.com`

**📝 الشرح:**

الثغرة هي CORS Misconfiguration (إعدادات CORS خاطئة) حيث يقوم الخادم بالاعتماد على قيمة ترويسة Origin القادمة من المستخدم والموجودة في الرابط (Query Parameter) بدلاً من ترويسة Origin الفعلية في الطلب. هذا يسمح للمهاجم بتزوير قيمة Origin إلى نطاق يتحكم به (evil.httpbin.org) وبالتالي يجعل الخادم يعيد ترويسة Access-Control-Allow-Origin بقيمة المهاجم مع Access-Control-Allow-Credentials: true. النتيجة هي أن أي موقع يستضيفه المهاجم يمكنه قراءة بيانات المستخدم المصادق عليه (Cookies/Session) عبر طلبات AJAX من المتصفح، مما يؤدي إلى تسريب معلومات حساسة أو تنفيذ إجراءات نيابة عن الضحية.

**🎬 خطوات الاستغلال:**

1. يقوم المهاجم بإنشاء صفحة HTML خبيثة على نطاق يتحكم به (مثل evil.httpbin.org).
2. يزرع في الصفحة كود JavaScript يستخدم fetch أو XMLHttpRequest مع خاصية credentials: 'include' لاستهداف نقطة النهاية على الخادم الضحية.
3. عند زيارة الضحية (المصادق عليه) للصفحة، يرسل المتصفح الطلب تلقائياً مع الكوكيز الخاصة بالضحية.
4. يضيف المهاجم باراميتر Origin=https://evil.httpbin.org في الرابط، فيقوم الخادم بقراءته واستخدامه في ترويسة Access-Control-Allow-Origin.
5. يعيد الخادم الرد مع Access-Control-Allow-Origin: https://evil.httpbin.org و Access-Control-Allow-Credentials: true.
6. يسمح المتصفح لسكربت المهاجم بقراءة محتوى الرد بالكامل لأن الأصل مطابق.
7. يقوم السكربت بإرسال البيانات المسروقة إلى سيرفر المهاجم عبر طلب POST.
8. يمكن للمهاجم أيضاً تنفيذ إجراءات حساسة (CSRF) باستخدام نفس الجلسة المسروقة.
9. تكرار الهجوم على نقاط نهاية أخرى (مثل /account, /api/user) لتوسيع نطاق التسريب.
10. أتمتة العملية باستخدام XSS مخزّن أو إعلانات خبيثة لزيادة عدد الضحايا.

**💻 كود PoC (جاهز للتنفيذ):**

```python
import requests
import urllib3

# تعطيل تحذيرات SSL (لأغراض الاختبار فقط)
urllib3.disable_warnings(urllib3.exceptions.InsecureRequestWarning)

# رابط PoC الكامل مع الباراميتر والحمولة
POC_URL = "https://httpbin.org?Origin=https://evil.httpbin.org"

# ترويسة Origin المزوّرة التي سيتم إرسالها في الطلب
HEADERS = {
    "Origin": "https://evil.httpbin.org",
    "User-Agent": "Mozilla/5.0 (CORS-PoC)"
}

# إرسال الطلب مع الكوكيز (لو وُجدت) لمحاكاة ضحية مصادق عليه
response = requests.get(POC_URL, headers=HEADERS, verify=False, timeout=15)

# طباعة رمز الحالة
print(f"[+] Status Code: {response.status_code}")

# فحص ترويسات CORS في الرد
acao = response.headers.get("Access-Control-Allow-Origin")
acac = response.headers.get("Access-Control-Allow-Credentials")
print(f"[+] Access-Control-Allow-Origin: {acao}")
print(f"[+] Access-Control-Allow-Credentials: {acac}")

# تحديد ما إذا كانت الثغرة قابلة للاستغلال
if acao == "https://evil.httpbin.org" or acao == "*":
    if acac and acac.lower() == "true":
        print("[!] VULNERABLE: CORS misconfiguration with credentials allowed!")
    else:
        print("[!] POTENTIAL: CORS reflects Origin but credentials not allowed.")
else:
    print("[-] Not vulnerable based on response headers.")

# طباعة جزء من محتوى الرد للتحليل
print("\n[+] Response body (first 500 chars):")
print(response.text[:500])
```

**🛠️ الإصلاح:**

يجب عدم الاعتماد على أي مدخل من المستخدم (Query Parameter, Header مخصص, Body) لتحديد قيمة Access-Control-Allow-Origin. بدلاً من ذلك، استخدم قائمة بيضاء (Whitelist) صارمة من النطاقات الموثوقة، وقارن قيمة ترويسة Origin الفعلية مع هذه القائمة. عند المطابقة، أعد نفس قيمة Origin في ترويسة الرد. تجنّب تماماً استخدام '*' مع Access-Control-Allow-Credentials: true. كما يُنصح بتقييد الطرق والترويسات المسموح بها، وإضافة ترويسة Vary: Origin لمنع التخزين المؤقت الخاطئ. في حالة عدم الحاجة إلى CORS، عطّله كلياً. يجب أيضاً تدقيق الكود بحثاً عن أي مكان يقرأ فيه Origin من الرابط أو من ترويسات غير قياسية.

**🛠️ كود الإصلاح:**

```python
# مثال إصلاح باستخدام Flask مع قائمة بيضاء صارمة
from flask import Flask, request, make_response

app = Flask(__name__)

# قائمة النطاقات الموثوقة فقط
ALLOWED_ORIGINS = {
    "https://app.example.com",
    "https://www.example.com",
}

@app.after_request
def add_cors_headers(response):
    # قراءة ترويسة Origin الفعلية فقط (وليس من Query Parameter)
    origin = request.headers.get("Origin")
    if origin and origin in ALLOWED_ORIGINS:
        response.headers["Access-Control-Allow-Origin"] = origin
        response.headers["Access-Control-Allow-Credentials"] = "true"
        response.headers["Access-Control-Allow-Methods"] = "GET, POST, OPTIONS"
        response.headers["Access-Control-Allow-Headers"] = "Content-Type, Authorization"
        # منع التخزين المؤقت الخاطئ
        response.headers["Vary"] = "Origin"
    return response

@app.route("/api/data")
def api_data():
    return {"secret": "sensitive-data"}

if __name__ == "__main__":
    app.run()
```
