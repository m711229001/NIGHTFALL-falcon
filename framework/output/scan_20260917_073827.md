### 1. [MEDIUM] Clickjacking: missing X-Frame-Options / CSP frame-ancestors

**التصنيف:** Clickjacking

**🎯 CVSS:** 5.3
  
**Vector:** `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N`
  
**⚠️ الأولوية:** 5

**🔗 رابط PoC (انسخه في المتصفح):**

```
https://httpbin.org
```

**📝 الشرح:**

الرابط المُدخل هو https://httpbin.org وهو خدمة اختبار HTTP عامة (HTTP Request & Response Service) تُستخدم بشكل شائع لاختبار الطلبات والاستجابات. لا يحتوي الرابط على باراميتر أو حمولة، ولا يوجد دليل على ثغرة فعلية. التصنيف المبدئي 'medium' لا يتوافق مع أي ثغرة معروفة في httpbin.org. قد يكون هذا إدخالاً ناقصاً أو خطأً في جمع البيانات. من المحتمل أن الهدف الحقيقي كان اختبار ثغرة SSRF أو Open Redirect عبر باراميتر مثل url= أو redirect=، لكن البيانات المقدمة لا تحتوي عليها.

**🎬 خطوات الاستغلال:**

1. تم استلام رابط بدون باراميتر أو حمولة محددة.
2. الرابط https://httpbin.org هو خدمة عامة وليست هدفاً لثغرة محددة.
3. لا يمكن بناء هجوم SSRF أو Open Redirect بدون باراميتر قابل للتلاعب.
4. تم افتراض أن الهدف قد يكون اختبار SSRF عبر باراميتر url، لكنه غير موجود في المُدخل.
5. تم إرجاع PoC يتحقق فقط من استجابة الخدمة للتأكد من أنها حية.
6. لا يوجد استغلال فعلي بسبب نقص البيانات.
7. يُنصح بإعادة جمع البيانات مع الباراميتر والحمولة الفعليين.
8. في حال كان الهدف اختبار SSRF، يجب توفير رابط مثل https://httpbin.org/redirect-to?url=http://169.254.169.254/.
9. في حال كان الهدف Open Redirect، يجب توفير رابط مثل https://httpbin.org/redirect-to?url=https://evil.com.
10. حالياً لا يمكن تأكيد وجود ثغرة.

**🛠️ الإصلاح:**

نظراً لعدم وجود ثغرة محددة في البيانات المقدمة، فإن الإصلاح العام يتضمن: (1) التأكد من جمع بيانات الثغرة بشكل كامل (الباراميتر، الحمولة، الدليل). (2) إذا كان الهدف خدمة httpbin.org، فهي خدمة اختبار عامة ولا تحتاج إصلاحاً. (3) إذا كان الهدف تطبيقاً يستخدم باراميتر url أو redirect، يجب تطبيق قائمة بيضاء للنطاقات المسموح بها، والتحقق من صحة المدخلات، ومنع الوصول إلى عناوين IP الداخلية (169.254.169.254، 127.0.0.1، 10.0.0.0/8، إلخ). (4) استخدام مكتبات آمنة للتحقق من صحة عناوين URL قبل إعادة التوجيه أو جلب الموارد.

**🛠️ كود الإصلاح:**

```python
from urllib.parse import urlparse
import ipaddress

# قائمة بيضاء للنطاقات المسموح بها
ALLOWED_HOSTS = {"api.example.com", "cdn.example.com"}

# نطاقات IP الخاصة التي يجب حظرها
PRIVATE_NETWORKS = [
    ipaddress.ip_network("10.0.0.0/8"),
    ipaddress.ip_network("172.16.0.0/12"),
    ipaddress.ip_network("192.168.0.0/16"),
    ipaddress.ip_network("127.0.0.0/8"),
    ipaddress.ip_network("169.254.0.0/16"),
]

def is_safe_url(url: str) -> bool:
    """التحقق من أن الرابط آمن لمنع SSRF و Open Redirect."""
    try:
        parsed = urlparse(url)
        # التحقق من البروتوكول
        if parsed.scheme not in ("http", "https"):
            return False
        # التحقق من النطاق ضمن القائمة البيضاء
        if parsed.hostname not in ALLOWED_HOSTS:
            return False
        # التحقق من عدم وجود IP خاص
        try:
            ip = ipaddress.ip_address(parsed.hostname)
            for net in PRIVATE_NETWORKS:
                if ip in net:
                    return False
        except ValueError:
            pass  # ليس IP، تم التحقق منه عبر القائمة البيضاء
        return True
    except Exception:
        return False

# مثال على الاستخدام
user_url = "https://api.example.com/data"
if is_safe_url(user_url):
    print("URL آمن")
else:
    print("URL غير آمن - تم رفضه")
```

### 2. [HIGH] CORS Misconfiguration

**التصنيف:** CORS

**🎯 CVSS:** 7.5
  
**Vector:** `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N`
  
**⚠️ الأولوية:** 1

**🔗 رابط PoC (انسخه في المتصفح):**

```
https://httpbin.org?Origin=https://evil.httpbin.org
```

**الرابط الأصلي:** `https://httpbin.org`

**📌 الباراميتر:** `Origin`

**💉 الحمولة:** `https://evil.example.com`

**📝 الشرح:**

الثغرة هي CORS Misconfiguration (إعدادات CORS خاطئة) حيث يقوم الخادم بالاعتماد على قيمة ترويسة Origin القادمة من المستخدم في ترويسة Access-Control-Allow-Origin دون التحقق من قائمة بيضاء. هذا يسمح لأي نطاق (مثل evil.httpbin.org) بقراءة استجابات الخادم عبر JavaScript من المتصفح. الخطورة عالية لأنها تسمح بسرقة بيانات المستخدم المصادق عليه (Tokens, PII) عبر طلبات cross-origin. في حالة httpbin.org قد تكون هذه بيئة اختبارية، لكن النمط نفسه خطير جداً في تطبيقات الإنتاج.

**🎬 خطوات الاستغلال:**

1. يقوم المهاجم بإنشاء صفحة HTML خبيثة على نطاق يتحكم به (evil.httpbin.org).
2. يزور الضحية الصفحة الخبيثة وهو مسجل دخوله في التطبيق الهدف.
3. تنفذ الصفحة طلب fetch() إلى https://httpbin.org مع credentials: 'include'.
4. يرسل المتصفح تلقائياً ترويسة Origin: https://evil.httpbin.org.
5. يستجيب الخادم بـ Access-Control-Allow-Origin: https://evil.httpbin.org و Access-Control-Allow-Credentials: true.
6. يسمح المتصفح للصفحة الخبيثة بقراءة الاستجابة كاملة.
7. يستخرج المهاجم البيانات الحساسة (CSRF tokens, session data, PII) ويرسلها إلى سيرفره.
8. يمكن أتمتة العملية عبر XSS أو حقن إعلانات لزيادة نطاق الضحايا.

**💻 كود PoC (جاهز للتنفيذ):**

```python
import requests

# رابط PoC الكامل مع الباراميتر والحمولة
POC_URL = "https://httpbin.org?Origin=https://evil.httpbin.org"

# ترويسة Origin الخبيثة التي سيتم إرسالها
HEADERS = {
    "Origin": "https://evil.httpbin.org",
    "User-Agent": "Mozilla/5.0 (CORS-PoC)"
}

def check_cors_misconfig():
    """
    يرسل طلباً مع Origin خبيث ويتحقق من ترويسات CORS في الاستجابة
    """
    try:
        # إرسال الطلب مع ترويسة Origin الخبيثة
        r = requests.get(POC_URL, headers=HEADERS, timeout=10, verify=False)
        
        print(f"[*] Status Code: {r.status_code}")
        print(f"[*] Request Origin: {HEADERS['Origin']}")
        print("\n[*] CORS Response Headers:")
        
        acao = r.headers.get("Access-Control-Allow-Origin")
        acac = r.headers.get("Access-Control-Allow-Credentials")
        
        print(f"    Access-Control-Allow-Origin: {acao}")
        print(f"    Access-Control-Allow-Credentials: {acac}")
        
        # تحليل النتيجة
        if acao == HEADERS["Origin"] or acao == "*":
            print("\n[!] VULNERABLE: Origin ينعكس في ACAO")
            if acac == "true":
                print("[!] CRITICAL: Credentials مسموح بها -> يمكن سرقة البيانات")
        else:
            print("\n[+] يبدو أن الخادم لا يعكس Origin (غير مصاب بهذا النمط)")
        
        # طباعة أول 500 حرف من الاستجابة
        print("\n[*] Response Body (first 500 chars):")
        print(r.text[:500])
        
    except requests.exceptions.RequestException as e:
        print(f"[!] خطأ في الطلب: {e}")

if __name__ == "__main__":
    check_cors_misconfig()
```

**🛠️ الإصلاح:**

1. لا تعكس قيمة Origin مباشرة في ترويسة Access-Control-Allow-Origin أبداً.
2. استخدم قائمة بيضاء (whitelist) صارمة للنطاقات الموثوقة فقط.
3. لا تستخدم '*' مع Access-Control-Allow-Credentials: true (المتصفحات ترفضها أصلاً).
4. تحقق من Origin عبر مطابقة كاملة (exact match) وليس عبر startswith أو contains.
5. تجنب السماح بـ null Origin لأنه يمكن تزويره من iframe sandbox.
6. أضف ترويسة Vary: Origin لتفادي مشاكل التخزين المؤقت.
7. راقب سجلات الطلبات بحثاً عن Origins غير معتادة.

**🛠️ كود الإصلاح:**

```python
from flask import Flask, request, jsonify

app = Flask(__name__)

# قائمة بيضاء صارمة للنطاقات الموثوقة
ALLOWED_ORIGINS = {
    "https://app.example.com",
    "https://admin.example.com",
}

@app.after_request
def add_cors_headers(response):
    origin = request.headers.get("Origin")
    
    # مطابقة كاملة (exact match) وليس contains/startswith
    if origin and origin in ALLOWED_ORIGINS:
        response.headers["Access-Control-Allow-Origin"] = origin
        response.headers["Access-Control-Allow-Credentials"] = "true"
        response.headers["Vary"] = "Origin"
    # إذا لم يكن Origin مسموحاً، لا نضيف أي ترويسة CORS
    
    response.headers["Access-Control-Allow-Methods"] = "GET, POST, OPTIONS"
    response.headers["Access-Control-Allow-Headers"] = "Content-Type, Authorization"
    return response

@app.route("/api/data")
def api_data():
    return jsonify({"secret": "sensitive-data"})

if __name__ == "__main__":
    app.run()
```

    "https://admin.example.com",
